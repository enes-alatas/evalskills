evalskills: system design

One shared VPS. Untrusted skill code runs only inside gVisor sandboxes on a dedicated Docker daemon. Your apps and the main daemon are untouched.

A: public, no secrets, no code execution B: trusted code, secrets, Docker access to the eval daemon only C: untrusted code, gVisor, egress to gateway only
Security
  • No container gets the main Docker socket
  • A: read-only FS, all caps dropped, non-root
  • Model key lives only in the gateway; trials get revocable per-run tokens
  • Hard caps: per trial, per day, total spend
Flow
  • Submit URL → pick skills → job queued
  • Static Tier 1 runs for everyone (free, fast)
  • Live Tier 3 for approved skills, on shared category tasks, with and without the skill
  • Results tied to commit + content hash; unchanged skills are not rerun
Scaling (no redesign)
  • More live throughput: raise the concurrency cap, or point the worker at E2B/a 2nd VM (one flag: --env-mode / DOCKER_HOST)
  • More traffic: more web replicas behind Caddy; SQLite → Postgres
  • Three containers + one daemon, all in one compose file + one systemd unit
