Static scans in a contained scanner

Proposal for #65. The app never runs SkillEvaluator itself. A sidecar with no network scans each skill and hands back only the report

Isolation
  • The scanner has no network, so nothing a skill contains can call out
  • It never sees the database, the clones or the public reports
  • No container gets any Docker socket, and the scanner has no env file
  • A read-only image and one job per container life mean nothing persists between scans
Flow
  • Unchanged skills (same commit and folder digest) are not rescanned
  • Scanner down: the job stays queued and shows as queued, never as a score
  • Past the time cap: failed, with the reason "scan timed out"
  • Each run records the image digest and the evaluator version
What it changes
  • It closes ADR-0002's interim exception from 11-09 (add-only amendment)
  • It needs no gVisor daemon. Tier 1 parses skills and runs none of their code
  • Live Tier 3 still runs under gVisor on docker-evals (ADR-0003)
  • Unit-tested here. The compose wiring is checked on the VPS with docker compose up
